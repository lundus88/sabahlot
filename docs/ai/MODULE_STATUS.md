- **2026-08-04 (`appMode`/`language`/`region` `localStorage` persistence bug fixed, `src/app/page.tsx`, no sprint ID -- owner asked to pick up outstanding work; presented as one of several candidates and explicitly chosen):** Root cause was already fully diagnosed in the 2026-07-30 pass below (`page.tsx:1131-1158`): the restore-from-storage effect defers its read via `queueMicrotask`, but the sibling `setStoredLanguage(language)`/`setStoredAppMode(appMode)`/`setStoredRegion(region)` effects run synchronously in the same commit -- including on the very first mount, not just on later changes -- writing the hardcoded `useState` defaults (`"en"`/`"public"`/`"sabah"`) to `localStorage` before the queued microtask ever reads the real stored value back, so the restore always observes its own overwrite and is a no-op. **New finding this pass:** `region` has the identical bug -- the original 2026-07-29 known-issue report and every subsequent mention only named `appMode`/`language`, but `region`'s `useState`/effect pair is structurally identical and was never called out. Fix: added a new `hasRestoredPreferences` boolean state, set `true` at the end of the restore effect's `queueMicrotask` callback; each of the three write-back effects now early-returns until that flag is `true`. This preserves the original SSR-hydration-safe design (the deferred `queueMicrotask` read is untouched -- switching to a lazy `useState` initializer instead was considered and rejected, since `getStoredLanguage()` et al. read `window` directly and would produce a server/client hydration mismatch on first render if called synchronously during the initial render). Verified with `npx tsc --noEmit` (clean), `npx eslint .` (0 errors, 31 pre-existing warnings unchanged), `npm run build` (succeeds), and all 17 pre-existing `.qa.ts`/`.qa.tsx` suites (zero regressions) -- plus, since none of those exercise this specific runtime timing bug, a real end-to-end browser test: launched `next dev`, drove a headless Chromium (global `playwright@1.56.1` + the container's pre-installed browser binary -- no new dependency added to this repo's `package.json`/lockfile) via a throwaway script in the scratchpad directory (not committed), seeded `localStorage` with non-default values, reloaded, and confirmed both via `localStorage` readback and a screenshot that the header UI itself reflected the restored language/mode/region.
