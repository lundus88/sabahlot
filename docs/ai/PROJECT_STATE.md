## Vision

SabahLot is a preliminary land-record and field-survey assistance tool for Sabah land matters. It helps public users, surveyors, and land officers capture, organize, and (increasingly) cloud-sync GPS points, drawn geometry, and case metadata for land applications, inheritance land, and customary land (NCR) cases. Every output is explicitly **preliminary** — not a legal survey plan, not proof of boundary, not an official approval by JTU, Land Office, or any authority.

- **Geometry cloud create/update** — backend merged in PR #16 (`main@b6d0a25`); UI wiring merged in PR #24 (`main@91e64c0`) via `src/lib/land-records/child-ui-sync.ts` (`syncParentGeometryToCloud`), called from `src/app/page.tsx`'s save flow immediately after the parent sync settles. Syncs only the one `drawingObjects` entry with `geometryType === "polygon"` and `category === "parent_lot"` — that entry's own id is reused as the geometry's cloud id (not the parent land record's id). If zero or more than one such object exists, the sync stays local-only / is rejected rather than guessing. Other drawn objects (proposed lots, lines, etc.) are not cloud-synced. Dev-gated only, same as parent sync; disabled in Production.
- **Points cloud create-only (backend) + create-only UI wiring** — backend merged in PR #21 (`main@d071d73`); UI wiring merged via **PR #35** (`main@a1e73a0950ac052c10e85657f1e75578b07ba3db`). UI: new `points-ui-sync.ts` (`syncFieldGpsPointsToCloud`), called from `src/app/page.tsx`'s save flow right after the geometry sync settles and before parties (call order: parent -> geometry -> points -> parties), reporting `FieldGpsLite.tsx`'s `points` state (the "Save Point"/Mark Point list only — not `foundPoints`/`foundPointRecords`, `trackLog`, or `targetPoint`, all of which remain entirely unsynced) up via a new `onPointsChange` callback prop. `pointType` is fixed to `"boundary_mark"` for every entry — a deliberate default, not an existing mapping, since `FieldGpsPoint` had no point-category concept at all before this. Every point already carries its own stable id from capture (ADR-001), so unlike parties there is no id-generation step. UI wiring is **create-only** (ADR-011/ADR-013): `land_points` has no `updated_at`, so an already-synced point edited locally and re-saved reports `points_out_of_sync`, never a false `points_synced` — relying on `points-write-coordinator.ts`'s already-verified 23505-retry/duplicate-content check (ADR-002), unmodified by this sprint. Sync results are tracked in a `pointsCloudSync` React state, deliberately not rendered. `index.ts` was not updated to barrel-export the new module. Dev-gated only, same as parent/geometry/parties sync; disabled in Production.
- **Parties cloud create+update (backend) + create-only UI wiring** — merged via **PR #31** (`main@f98445c8493f1764188ab6de8cf5f905274b0f51`). Backend: `parties-repository.ts` / `parties-write-coordinator.ts` / `parties-validation.ts` / `parties-cache.ts` — full create+update, minus `id_number` (ADR-014; structurally absent from the writable-input type, explicitly regression-tested). UI: new `parties-ui-sync.ts` (`syncPdfIdentitiesToCloud`), called from `src/app/page.tsx`'s save flow after parent, geometry, and points sync each settle (current call order: parent -> geometry -> points -> parties), syncing each filled-in `PdfIdentityFields` entry (surveyor/witness/villageHead/applicant -> `surveyor`/`witness`/`village_head`/`original_applicant`; no "owner" slot in this form). UI wiring is **create-only**: `CloudLandParty` has no `updatedAt`, so there is no safe token for `updateCloudParty`'s concurrency filter from the UI layer; a previously-synced identity is re-CREATEd with its persisted id every save instead, relying on the backend's already-verified 23505-retry/duplicate-content check (never a silent overwrite) — the backend's UPDATE path exists but is not called from the UI yet. A client-generated UUID is assigned on first sync and persisted back via `PdfIdentityPerson.id`, round-tripped through the existing `STORAGE_KEY` auto-save effect. No UI/layout was changed; sync results are tracked in a `partiesCloudSync` React state, deliberately not rendered. `index.ts` was not updated to barrel-export the new parties module (both parties sprints scoped it out). Dev-gated only, same as parent/geometry sync; disabled in Production.
